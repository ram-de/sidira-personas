# sidira-personas

Per-company persona calibration for [Sidira](https://github.com/ram-de/sidira-simulator).

Takes a user-level dataset organized into a **fixed set of feature groups** (with variable metrics inside each group) and emits a **Persona Pack** — a versioned JSON artifact that defines the personas, their population weights, and an LLM system prompt for each persona.

The Persona Pack is consumed by the Sidira simulation engine to seed agent populations that faithfully represent a real company's userbase.

## The Fixed Schema

Seven feature groups. Constant across companies. Metrics inside each group are company-specific.

1. Demographic & Identity
2. Behavioral Patterns
3. Motivations & Jobs-to-be-Done
4. Pain Points & Friction
5. Value Sensitivity
6. Channel & Tech Behavior
7. Loyalty & Lifecycle Stage

## Pipeline

```
User dataset (Snowflake / Parquet / CSV)
   ↓ A — Adapter        normalize per group (company-specific)
   ↓ B — Encoder        PCA per group → fixed-width embedding
   ↓ C — Cluster        GMM (BIC-selected k) on concatenated embeddings
   ↓ D — Calibrate      weights (headcount / orders / revenue) + bootstrap stability
   ↓ E — Compile        persona centroid → LLM system prompt
   ↓
Persona Pack JSON  +  persona_prompts/*.md
```

## Quickstart

```bash
pip install -e .
sidira-personas run --config config/<company>.yaml
```

### Try it end-to-end (no Snowflake, no API key)

A fully synthetic fixture ships in-repo so the whole pipeline is runnable and
CI-testable without any real data (the real-company `config/`/`samples/` were
purged in #9):

```bash
python fixtures/synthetic_company.py                          # (re)materialize the parquet
sidira-personas run --config config/synthetic.yaml --no-llm   # run all 6 layers
```

The fixture embeds 4 separable latent segments + a lifecycle prefilter (non-Active
rows → FIXED_* personas) and exercises every adapter type. `tests/test_pipeline_smoke.py`
drives this same path and asserts the v1.1 + #7 pack contract end-to-end (#12).

Outputs land in `outputs/<run_id>/`:
- `persona_pack.json`
- `prompts/P01.md … P0N.md`
- `assignments.parquet` (user_id → persona_id)
- `report.html` (cluster diagnostics, weights, stability)

## Status

v0.2 — LLM-first naming (company-agnostic) with generic numeric fallback.

## Naming

Persona names + descriptions + job-to-be-done are generated by an LLM at pack build time:
- **Primary path (LLM):** provider preference is **Groq → Anthropic**.
  - If `GROQ_API_KEY` is set, calls Groq's OpenAI-compatible endpoint (default model `llama-3.3-70b-versatile`, override with `GROQ_MODEL`).
  - Else if `ANTHROPIC_API_KEY` is set, calls Claude (default `claude-sonnet-4-6`, override with `ANTHROPIC_MODEL`).
  - The prompt only sees `{company_id, feature names, persona values, z-deltas vs baseline}` — fully company-agnostic.
- **Fallback path:** if no API key, network fails, JSON parse fails, or `--no-llm` flag is passed, every persona is named `Persona01`, `Persona02`, … with a description listing the top-3 distinctive features. The pipeline never hangs on the LLM call.

To force the fallback path: `sidira-personas run --config <yaml> --no-llm`.

## Follow-ups

1. **Per-cluster stability.** ✅ **landed** (ram-de/sidira-personas#7). Per-cluster **bootstrap Jaccard** (clusterboot-style, with Hennig's interpretation bands) replaces the global-ARI-only signal — each discovered persona carries its own `stability` + `stability_verdict` (≥0.85 highly stable, ≥0.75 valid, ≤0.5 dissolved), `posterior_entropy` measures assignment ambiguity / cluster overlap (a falsely-crisp identity is what collapses downstream agent variance), and FIXED_* personas no longer fake `stability=1.0` (now `null`). A **train/test holdout** diagnostic (held-out log-likelihood + proportion drift) lands in `persona_pack.json` `notes`. `overall_stability` (mean ARI) is retained as a coarse back-compat number. **Compat:** `Persona.stability` is now nullable; the simulator consumer's `Persona` model has no `stability` field (Pydantic ignores extras) and pins `schema_version ∈ {1.0, 1.1}`, so this stays within the 1.1 line and the new fields are safely ignored by old consumers.
2. **HTML diagnostic report.** BIC curve, weight distributions, t-SNE scatter of the embedding colored by cluster, baseline crosstab. Useful before any cluster ships to Sidira.
3. **Per-cluster orders/revenue concentration alerts.** When a small cluster carries an outsized share of value (headcount share ≪ value share), the Persona Pack should surface that as a "high leverage" flag for simulation cohort selection.
4. **Schema versioning.** ✅ **v1.1 landed** (additive) to unblock the simulator's per-agent individual-row
   layer (ram-de/sidira-personas#7). Each `Persona` now also carries `centroid_full` (mean over all adapted
   features), `feature_scale` (within-cluster std — the step-2 z-score denominator), `sample_rows` (N
   covariance-aware synthetic rows, privacy-clean), and `posterior_mean` (mean GMM soft membership; `None`
   for FIXED_* personas). `assignments.parquet` also gains `post_P*` soft-posterior columns. The fields are
   additive (defaulted), so v1.0 packs still parse. The same v1.1 line later gained the #7 honesty fields
   (`stability_verdict`, `posterior_entropy`, nullable `stability`) — additive, so old consumers ignore them.
5. **Methodology rebuild.** Reconceive the feature ontology, segmentation method, synthetic-individual
   generation, and validation protocol from first principles — see the methodology doc (in progress).
