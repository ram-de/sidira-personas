# Sample Persona Pack — Run #10 (LLM naming via Groq)

Source: `PRODDB.RAMKUMARKARUNANIDHI.CHANNEL_TECH_FEATURES_10K` (10,000 users, snapshot 2026-05-14)

## What changed from run #9

Every persona's name, description, and JTBD is now generated by an LLM at pack-build time — no hard-coded company-specific rules.

- Provider: **Groq** (`llama-3.3-70b-versatile` via the OpenAI-compatible API)
- Prompt sees only `{company_id, top-20 feature z-deltas vs. baseline, actual feature values}`
- Output: structured JSON `{name, description, jtbd}` per persona
- Fallback path (no API key, network error, JSON parse error, or `--no-llm` flag): generic `Persona01`, `Persona02`, … names with description listing top-3 distinctive features

## Architecture genericity restored

Layer E (prompt compiler) now has **zero DoorDash-specific code**. The same pipeline run against an Uber/Instacart/Shopify dataset would produce semantically meaningful persona names for that company — the LLM reads the actual feature names and z-deltas, no per-company rules required.

## How to reproduce

```bash
export GROQ_API_KEY=<your_groq_key>
# Optional: override default model
# export GROQ_MODEL=llama-3.3-70b-versatile

cd ~/Projects/pythia-personas
source .venv/bin/activate
pythia-personas run --config config/doordash.yaml
```

Provider preference: `GROQ_API_KEY` → `ANTHROPIC_API_KEY` → fallback. Pass `--no-llm` to force generic names regardless of env keys.
